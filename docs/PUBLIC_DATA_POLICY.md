# HNBLUE 公开数据与知识策略

## 1. 默认原则

公开仓库展示“如何设计和实现”，不展示“真实业务内容是什么”。除已明确列入版本控制的合成样例、公开许可代码资产和必要的公开引用材料外，数据默认不发布。

## 2. 可提交内容

- 源代码、测试代码、数据库 Schema 和不含生产值的配置样例；
- `data/examples/` 中明确标注为 fabricated/synthetic 的小型 CSV；
- `rag/examples/knowledge/` 中用于验证检索与拒答逻辑的合成知识；
- 仅用于界面定位的公开基础行政区边界几何，不附带观测指标、业务图层或精细采样点；
- 公开来源的链接、许可信息和最小必要元数据；
- 不含主机、账号、密钥、内部路径和真实响应明细的架构说明。

## 3. 禁止提交内容

- 政府、机构、项目或个人提供的未公开文档与知识库；
- 真实 RAG source、chunks、embedding、索引 manifest 和真实评测题；
- 生产/测试数据库导出、Redis/MySQL 数据卷、消息历史和用户资料；
- API Key、JWT 密钥、数据库/邮件密码、Cookie、Token、私有 `.env`；
- 原始样地、通量、UAV/遥感原始数据、精细位置和未授权论文全文；
- 发布包、服务器配置备份、日志、请求级压测 CSV、截图缓存和浏览器 profile；
- 可能暴露内部域名、IP、账号、审批流程细节或安全控制参数的交付证据。

## 4. RAG 私有部署方式

私有知识保存在仓库外目录，通过 `HNBLUE_RAG_SOURCE` 只读挂载。`rag/build_index.py` 将索引写到同样不受 Git 跟踪的 `rag/artifacts/` 或运维指定目录，再通过 `HNBLUE_RAG_CHUNKS` 加载。

公开示例与私有资料必须使用不同目录，避免开发者误把真实知识复制到 `rag/examples/knowledge/`。生成索引继承源知识的敏感级别，不能因为格式变成 JSONL 就视为可公开。

## 5. 脱敏规则

- 将真实组织、人员、账号、主机、路径和工单号替换为中性示例；
- 将真实区域精细位置替换为“示例区域甲/乙”等虚构名称；
- 将真实数值替换为不保持统计分布的构造值，避免可逆推断；
- 删除自由文本中的身份信息、内部意见和未公开政策解读；
- 图片需要重新确认来源、许可和隐私，不能只依赖文件名判断；
- 文档中保留方法、字段和架构，删除真实内容、规模、时间与运行证据。

## 6. 发布前检查

1. 只查看 Git 将要提交的文件，而不是整个本地目录。
2. 搜索常见密钥、Token、密码、私钥、连接串、邮箱、IP 和内部组织名称。
3. 检查大文件、压缩包、数据库、模型输入、请求日志和生成索引。
4. 确认样例文件有 synthetic/fabricated 声明。
5. 确认 README、架构和 API 没有引用已删除的私有依赖。
6. 在提交、推送和发布后再次查看 GitHub 文件列表与 release 资产。
