# Redis API 限流压测报告

## 1. 测试背景与目标
为验证 HNBLUE 系统中基于 **Redis + Spring Boot 拦截器** 的 API 限流策略效果，使用 Python 自编压测脚本模拟高并发异常请求。目标是检验在持续高压下，Redis 限流是否能够稳定拦截异常请求，防止恶意攻击和缓存击穿。

## 2. 测试环境
- **后端框架**：Spring Boot + MySQL  
- **缓存与限流**：Redis Cluster，互斥锁用于缓解缓存击穿  
- **测试工具**：Python 自研压测脚本（模拟 Vegeta 功能，固定 RPS）  
- **硬件环境**：Windows 10 + OpenJDK 64-Bit Server VM  

## 3. 测试方案
按照不同时间长度进行多轮压测：
- 短时验证：1 分钟与 10 分钟
- 长时验证：1 小时（稳定性与持续拦截能力的核心验证）

压测方式：  
持续向 `http://localhost:8088/api/login` 发送 **POST** 异常请求，固定速率 **10 RPS**，每个请求均为无效的登录凭证。

## 4. 关键结果
以 1 小时稳定压测数据为例：
- **计划请求数**：36,000  
- **实际发送数**：36,000  
- **达到的平均 RPS**：9.95  
- **HTTP 2xx**：0  
- **HTTP 4xx**：约 36,000，其中 **429 (Too Many Requests)** ≈ 35,700  
- **其他 4xx**：约 300  
- **5xx / errors**：0  
- **延迟中位数 (p50)**：≈ 12.75 s  
- **延迟 95 分位 (p95)**：≈ 15.26 s  

从数据可见，在长时间持续高压的情况下，Redis 限流策略有效拦截了 **约 99% 的异常请求**（35,700 / 36,000 ≈ 99.2%），并且在 1 小时测试中保持了稳定的拒绝响应。

## 5. 结论与意义
1. **稳定性**：1 小时持续压测期间，Redis 限流无明显波动，API 始终维持约 10 RPS 的请求压力。  
2. **高效拦截**：异常请求中约 99% 被返回 429 状态码，表明限流策略能在真实高并发环境下有效保护后端服务。  
3. **系统安全性**：与盐+哈希策略共同作用，保障了用户密码安全与服务可用性。  
4. **实用价值**：该方案可直接应用于生产环境，应对恶意刷接口、爬虫等攻击场景。

## 6. 后续工作
- 建议在生产环境中定期执行类似长时压测，验证限流配置在升级与流量变化后的稳定性。  
- 可根据业务增长情况，动态调整限流阈值与 Redis 集群资源。

---

**结论**：基于 Redis 的 API 限流方案在 HNBLUE 系统中经长时间高压验证，成功将异常请求拦截率稳定在 99% 左右，显著提升了系统抗压与安全防护能力。
