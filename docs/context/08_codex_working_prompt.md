# Codex 工作提示词

你现在接手 HNBLUE 项目。请先阅读 `docs/context/` 下的全部 Markdown 文件和 `assets/database_architecture.png`，再阅读项目根目录 README、前端代码、后端代码、模型服务代码、数据库脚本和运行说明。

HNBLUE 是海南蓝碳数字化应用系统。V1.0 已经具备 Vue 前端、Spring Boot 后端、MySQL、Redis、Flask/CatBoost 模型服务、AnythingLLM + DeepSeek API 智能问答和 ECharts 可视化。V2.0 目标是降低启动复杂度，整理数据库与数据目录，构建文昌示范区专题，补充遥感/无人机/通量塔等数据的元数据管理能力，形成可部署、可演示、可扩展的工程版本。

请不要从零重写整个系统。优先在现有代码基础上完成可运行重构。请先输出一份项目体检报告，内容包括：（1）项目目录结构；（2）前端、后端、模型服务、数据库、Redis、AI 助手的当前状态；（3）启动阻塞点；（4）缺失配置；（5）数据库脚本状态；（6）最小可运行路径；（7）两周内可完成的开发任务拆分。

完成体检后，请按以下顺序推进：第一，整理环境变量与启动说明，提供 `.env.example`、端口说明和服务启动顺序。第二，整理数据库脚本，至少形成 `db/schema.sql`、`db/seed_wenchang_demo.sql`、`db/data_dictionary.md`。第三，补充文昌示范区数据结构和演示数据，明确真实数据、公开数据、模拟数据、待接入数据的区分字段。第四，完善前端文昌专题页面，包含数据目录、碳储量指标、碳通量指标、遥感产品元数据、模型估算入口和 AI 碳助手入口。第五，整理部署方案，优先尝试 Docker Compose；若无法完成容器化，则提供明确的本地启动说明。

开发过程中请遵守以下边界。完整 WebGIS 和 ArcGIS 空间分析暂不作为硬性目标。可先使用 ECharts 地图、静态图件、元数据列表和文件下载入口实现演示。真实通量塔和无人机数据若尚未交付，请保留待接入状态和模拟数据标识。CatBoost 模型作为辅助评估和解释模块，不要写成已经完成省域精确核算。AI 碳助手应服务于指标解释、模型解释、数据口径说明和不确定性提示。

每完成一个阶段，请提交可核查结果，包括改动文件清单、运行命令、截图建议、测试方式和仍然存在的问题。优先保证项目可以被下载、配置、启动、访问和演示。
