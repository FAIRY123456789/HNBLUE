# 外部数据集数据库审计

审计时间：2026-07-17（Asia/Shanghai）
目标数据库：`hnblue_v2_dev_control`
审计原则：只读、不输出密码/Token/Salt/用户信息、不在无证据时声明数据库与文件完全一致。

## 1. 结论摘要

- 当前运行中的 Spring Boot 后端确认目标数据库可读；其健康接口确认 5 张核心业务表可读：`t_indicator_dictionary` 199 条、`t_data_source` 68 条、`t_satellite_mangrove_cover` 96 条、`t_satellite_region_metric` 294 条、`t_literature_carbon_record` 70 条。
- `t_data_source` 中可检索到 BAAD 和 Tallo 的来源登记；未检索到 ChinAllomeTree 来源登记。数据库中另有两条 **GMW（Global Mangrove Watch）** 来源登记，但它们与本轮本地 **GWM 海岸与海洋湿地十表** 不是同一数据资产，未混用。
- 本轮审计终端没有 `DB_PASSWORD`，且没有 MySQL 命令行客户端；直接使用 JDBC 空密码连接被 MySQL 拒绝。现运行后端没有暴露 `SHOW TABLES` 或 `information_schema` 审计接口，因此无法在不提取运行进程凭据的前提下确认候选外部记录表是否存在。
- 由于数据库外部记录表尚未得到证据确认，前端最终采用本地原始 CSV 的后端只读分页；新服务在运行时仍会对白名单候选表执行 `information_schema` 检查，一旦目标库存在对应表便优先使用 MySQL。
- 14 个原始 CSV 均存在并可完整解析，共 528,420 条记录。未发现结构错行；BAAD 文件发现 333 条完全重复行，需在任何受控入库前明确其业务含义并制定去重键。

## 5. 数据质量发现

### BAAD 完全重复行（中等风险，高置信度）

- 证据：21,084 条记录中有 333 条完整行与先前记录完全相同，占 1.58%。
- 风险：若直接导入并把每行视为独立样本，可能放大重复样本权重。
- 处置：当前只读浏览保留源文件内容，不因前端展示修改数据值；受控入库前应使用 BAAD 原始研究、个体和测量粒度确定组合键，再决定是否去重。

### Tallo 缺失值规模较大（低至中等风险，高置信度）

- 证据：498,838 × 13 个单元格中有 431,643 个空值。
- 解释：Tallo 允许一条记录只具有胸径、树高或冠幅中的部分测量；缺失不自动视为导入失败。
- 处置：页面明确显示缺失值，不做零值填充；模型或统计使用时应按目标字段重新计算有效样本量。

### 数据库—文件一致性尚未完成（高风险，高置信度）

- 证据：缺少可在当前审计终端使用的数据库运行凭据，无法抽取候选外部表的行数、字段、主键、索引和随机 20 行。
- 影响：本轮不能声明任何候选 MySQL 外部表与 CSV 完全一致，也不能判断是否存在重复导入或部分字段导入。
- 处置：保持 CSV 只读来源；获得只读凭据后执行 `scripts/ExternalDatasetDatabaseAudit.java` 的扩展审计，再把结果写回清单。

## 7. 最终数据源决策

本轮采用本地原始 CSV，由 Spring Boot 后端流式读取并按需分页；浏览器不会加载完整 41 MB Tallo 文件。服务每次先检查当前数据库是否存在白名单整理表：存在时使用 MySQL 服务端分页，不存在或数据库连接不可用时使用 CSV。未执行数据库建表、写入、覆盖或删除操作。
