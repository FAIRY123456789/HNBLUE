# HNBLUE 系统架构说明（ARCHITECTURE）

## 1. 系统目标与范围
HNBLUE 面向蓝碳生态系统的数据集成、建模与可视化应用场景，提供多源数据治理、碳储量模型预测与可解释性分析、基于私域知识的大模型问答，以及前后端一体化的交互式可视化展示。系统聚焦单机开发环境的稳定运行与架构清晰性，强调各模块的职责边界与接口契约。

## 2. 运行拓扑与启动顺序
系统由五个主要部分构成，并在本地以固定顺序启动：  
1. 桌面版 AnythingLLM：大模型接入层，连接 DeepSeek API 与私域知识库  
2. Redis Cluster：运行在本机 VMWare 的 `node1` 节点内，以六个容器组成集群  
3. Spring Boot 后端：在 IntelliJ IDEA 中启动，接入 MySQL 与 Redis，提供 REST 接口  
4. Vue 前端：在 VS Code 中执行 `npm run serve` 启动，作为用户交互层  
5. Flask 模型服务：在 PyCharm 中启动，封装 CatBoost 推理与 SHAP 解释  

完成以上五步后，即可通过前端访问系统功能。

## 3. 体系结构分层
系统按照“数据层—服务层—模型层—交互层—智能助手”分层：  
- **数据层**：MySQL 承载核心业务数据，Redis Cluster 提供分布式互斥锁与限流能力  
- **服务层**：Spring Boot 负责用户认证、权限管理、指标接口与业务数据访问  
- **模型层**：Flask 独立运行，向前端暴露 CatBoost 推理与 SHAP 解释接口  
- **交互层**：Vue.js 前端集成 ECharts，实现指标对比、时间序列与地图可视化  
- **智能助手**：AnythingLLM 连接 DeepSeek 与私域知识库，面向知识问答与解释生成  

## 4. 关键组件与职责
- **Spring Boot 后端**  
  1. 认证与访问控制：颁发和校验令牌，区分 Admin 与 User  
  2. 用户与指标接口：处理用户资料管理、区域与指标的查询  
  3. 防护与限流：依托 Redis Cluster 实现接口限流与互斥锁机制  
  4. 审计与日志：记录请求与异常，支持功能测试与并发测试  

- **Flask 模型服务**  
  1. 暴露单样本与批量预测接口 `/api/predict-carbon` 与 `/api/predict-carbon/batch`  
  2. 提供解释性接口 `/api/sensitivity-explain` 与 `/sensitivity_plots/<filename>`，返回敏感性分析结果  

- **Vue 前端**  
  1. 提供用户登录、注册、个人信息、管理员管理等交互模块  
  2. 负责可视化，包括区域总览、详情页、参数敏感性分析、响应曲线与文献比对  

- **AnythingLLM 智能助手**  
  - 集成 DeepSeek 与本地知识库，提供问答与解释辅助，不参与核心数据流  

- **Redis Cluster**  
  - 提供分布式互斥锁与令牌桶限流，用于提升系统稳健性  

- **MySQL**  
  - 保存用户、区域、指标、日志等结构化数据，保证一致性与可追溯性  

## 5. 服务间通信与契约
系统存在两条主要调用链：  
1. **前端 → 后端**：Spring Boot 提供 `/api/*` 接口，涵盖认证、用户、区域与指标相关操作，响应统一采用 JSON 格式。  
2. **前端 → Flask**：Flask 独立运行并提供 `/api/predict-carbon` 与 `/api/sensitivity-explain` 等模型接口，前端直接调用，CORS 设置允许前端来源。  

## 6. 数据流与处理链路
典型交互场景包括：  
- **可视化数据流**：前端请求 Spring Boot → 后端查询 MySQL 或 Redis → 结果返回前端 → ECharts 渲染图表  
- **模型推理流**：前端提交参数 → 请求 Flask → Flask 完成推理与 SHAP 解释 → 前端渲染结果  
- **智能问答流**：前端请求 Spring Boot → 后端触发 AnythingLLM → 桌面端调用 DeepSeek 与私域知识库 → 前端展示结果  

## 7. 安全与合规
系统认证基于令牌，前端在路由守卫中校验令牌状态，并按用户类型控制页面访问。后端接口启用限流与鉴权，用户密码以盐+哈希存储。跨域访问按白名单控制来源与请求头，日志避免记录敏感信息。对外 API（DeepSeek）与知识库接入遵循其使用条款，公开仓库不包含任何密钥。

## 8. 数据模型与存储约定（摘要）
关系数据库涵盖用户、区域、指标等核心表，字段设计包含标识、时间、来源与单位，保证追溯性。指标表采用“区域×时间×指标项”作为维度，便于时间序列查询与可视化。常用查询路径加索引，模型中间数据与图像结果不进入事务表，可按需缓存至 Redis 或以静态文件形式提供。

## 9. 模型与可解释性
CatBoost 用于碳储量预测，Flask 提供推理接口 `/api/predict-carbon` 与 `/api/predict-carbon/batch`。前端可直接消费数值型 JSON 或基于图像路径进行渲染。

## 10. 智能助手集成
AnythingLLM 桌面端结合 DeepSeek 与私域知识库，提供辅助问答与解释，不写入业务数据路径。交互模式为“外部分工，前端内嵌”，前端在需要时展示助手的回答，用户可结合业务数据进一步验证。

## 11. 可观测性与测试
Spring Boot 与 Flask 服务均输出结构化日志，记录请求耗时与错误码。功能测试基于 JUnit，覆盖用户与指标接口；并发测试基于 JMeter，关注错误率与吞吐能力。可视化部分通过关键视图截图与数值校验结合的方式进行回归验证，测试结果统一归档至 `docs/`。

## 12. 故障与降级
当 Flask 不可用时，前端获得错误提示，模型相关功能不可用但业务接口仍正常。Redis Cluster 异常时，后端短暂降级为直读 MySQL，限流与互斥功能暂时停用。AnythingLLM/DeepSeek 失效时仅影响智能助手功能，不影响业务与模型主链路。

## 13. 配置与环境
配置文件与密钥分离管理，仓库仅包含示例配置与脱敏样例。Redis Cluster 统一运行在 `node1` 虚拟机上，后端通过集群地址接入。前端与 Flask、Spring Boot 的端口需保持与 CORS 策略一致。  

## 14. 架构演进路线
后续演进优先考虑：  
1. 参数化限流与互斥策略并与监控系统联动  
2. 增加只读缓存与异步刷新，提升查询稳定性  
3. 扩展模型接口容错能力，增加退避与重试策略  
4. 完善指标字典与单位换算机制，保证跨视图一致性  
5. 制定契约测试与文档自动生成机制，降低前后端联调成本
